Guida al server dedicato Bedrock

Come aggiungere add-on a un server Minecraft Bedrock

Per installare add-on su un server Minecraft Bedrock, arresta e salva il server dedicato, copia ogni pack estratto nella cartella corretta e registra UUID header e versione nell'elenco del mondo attivo. Inizia con un solo pack e fai una prova con un secondo account prima di aggiungerne altri.

Questa procedura basata sui file è per un Bedrock Dedicated Server (BDS) gestito da te. È diversa dall'importazione di un file .mcaddon nel tuo mondo locale e non offre accesso diretto ai file di un Realm o al pannello privato di un hosting. Controlla manifest e versione del server prima di modificare un mondo condiviso.

Risposta rapida

Copia i file sul server e collegali al mondo che viene caricato

Un Bedrock Dedicated Server non installa un add-on aprendo un file .mcaddon nella console. Quel formato semplifica l'importazione in un client Bedrock. Per BDS, estrai le cartelle dei pack, separa i behavior pack dai resource pack e copiali nelle directory corrispondenti accanto ai file del server.

Il server usa soltanto i pack registrati per il mondo caricato. Aggiungi l'UUID header e la versione del manifest a world_behavior_packs.json o world_resource_packs.json di quel mondo. Lascia manifest.json nella cartella del pack e usa l'UUID header, non l'UUID di un modulo o il nome della cartella.

Prima di modificare i file, fai una copia completa del mondo e arresta BDS, così il processo non sovrascrive i cambiamenti. Prova la copia con un account amministratore e uno standard. Conserva la copia di ripristino finché un riavvio e una normale sessione di gioco non terminano senza problemi.

La scheda sorgente Verity Bedrock controllata il 23 settembre 2026 riporta ThatMob's Verity 4.0.0 per V26.50, caricato il 17 settembre 2026. La scheda identifica una pubblicazione del pack, ma non dimostra la compatibilità con ogni server dedicato, Realm o mondo. Verifica il manifest e le note della fonte per l'ambiente specifico.

Behavior pack

Aggiunge o cambia regole ed entità lato server. Va in behavior_packs e deve comparire nell'elenco dei behavior pack del mondo attivo.

Resource pack

Fornisce texture, suoni e altre risorse visibili ai client. Va in resource_packs; controlla se chi entra deve accettare il file scaricato.

Ambito del mondo

La presenza di una cartella non attiva il pack. Gli elenchi dei pack del mondo e la configurazione del server determinano quali contenuti vengono caricati.

Installazione

Aggiungere un pack a BDS con sette verifiche

Segui questo ordine su un BDS autogestito. I pannelli hosting possono cambiare nomi e percorsi, ma le verifiche su mondo e manifest restano necessarie.

1

Verifica tipo di server e mondo attivo

Accertati di gestire un Bedrock Dedicated Server e non un Realm. Leggi level-name in server.properties: indica la cartella del mondo sotto worlds. Con hosting gestito, segui il file manager e le istruzioni del provider invece di presumere che il percorso locale BDS sia uguale.

2

Confronta il pack con la versione del gioco

Apri manifest.json e controlla format_version, minimum_engine_version, UUID e versione header, oltre alle dipendenze. Confrontali con la release effettiva del server e il tipo di pack supportato. Nome del file e pagina del progetto non bastano da soli a dimostrare la compatibilità.

3

Ferma il processo e crea un backup

Arresta BDS correttamente prima di toccare i dati del mondo. Copia tutta la cartella del mondo attivo e salva anche gli elenchi dei pack e server.properties. Annota nome del mondo e data per ripristinare il salvataggio giusto se il server non si avvia.

4

Estrai e separa le cartelle

Estrai il pacchetto scaricato e trova la cartella che contiene direttamente manifest.json. Metti i behavior pack in behavior_packs e i resource pack in resource_packs. Evita un livello di cartelle in più e non lasciare il pack nell'archivio .zip o .mcaddon.

5

Registra il pack per quel mondo

In worlds/<nome-mondo>/ aggiungi un oggetto per ciascun pack nel file world_behavior_packs.json o world_resource_packs.json corretto. Usa pack_id per l'UUID header e version come matrice di tre numeri dello stesso header. Mantieni JSON valido e rispetta le dipendenze.

6

Controlla le risorse per i client

Se il mondo usa un resource pack, verifica texturepack-required in server.properties. Se attivo, i client compatibili devono accettare il file scaricato offerto; non garantisce che ogni risorsa sia resa correttamente su qualsiasi dispositivo. Spiega la richiesta prima del test.

7

Riavvia e prova una copia

Avvia il server e controlla console o log per errori di manifest, dipendenze e JSON. Entra con un client compatibile, verifica regole e grafica, quindi ripeti con un secondo giocatore. Porta il cambio nel mondo principale solo dopo un riavvio pulito e con un piano di ripristino.

File e ambito

La cartella d'importazione client non è quella del mondo BDS

Su un dispositivo personale, aprire un .mcaddon può importare il contenuto nel profilo Bedrock locale, spesso dentro una cartella com.mojang. Quello spazio client è diverso dalle directory behavior_packs, resource_packs e worlds del server. Copiare un file solo sul tuo PC non fa caricare il pack al server dedicato.

I percorsi BDS variano in base a sistema operativo, installazione, container e pannello hosting. Parti dalla directory con eseguibile del server e server.properties, poi verifica level-name. Un pannello può mostrare una radice virtuale: segui la mappatura del provider e non incollare un percorso Windows ipotizzato in un container Linux.

Mantieni manifest.json insieme ai file del pack. L'UUID header identifica il pack nell'elenco del mondo; gli UUID dei moduli hanno uno scopo diverso. Se il creatore dichiara dipendenze, installa anche quei pack e usa esattamente ID e versioni presenti nei relativi manifest.

Sincronizzazione e pack multipli

Il pack server e l'add-on locale del giocatore non sono sempre la stessa cosa

Un server può offrire ai client il resource pack associato al mondo. texturepack-required stabilisce se il giocatore deve accettarne il trasferimento per entrare. Non installa il behavior pack come add-on locale, non corregge un pack incompatibile e non assicura la stessa grafica su tutte le piattaforme. Prova le versioni esatte di server e client che userai.

I behavior pack di solito fanno parte della configurazione del mondo sul server; i resource pack forniscono risorse visive e audio ai client. Alcuni add-on includono entrambi. Registra ogni parte nell'elenco corretto: vedere una texture non dimostra che il behavior pack funzioni, e vedere un'entità non prova che tutti gli asset siano arrivati.

Più add-on possono dipendere l'uno dall'altro. Installa tutte le dipendenze dichiarate, cerca UUID header duplicati e mantieni allineata la versione degli elenchi con la cartella installata. Rispetta l'ordine o gli esperimenti richiesti per quella release. Aggiungi un pack alla volta a una copia del mondo.

Le frecce dell'illustrazione mostrano il confine concettuale: chi gestisce il server abilita i pack; i client si collegano e possono ricevere risorse. È un'immagine esplicativa, non una schermata di Minecraft, un pannello o una traccia di rete verificata.

Risoluzione dei problemi

Perché un add-on sembra installato ma non cambia il server

Usa il sintomo per individuare il controllo successivo. Cambia un solo elemento per volta e conserva il backup finché il mondo corretto non si carica bene.

È caricato un altro mondo

Confronta level-name con la cartella di cui hai modificato gli elenchi. Un pack valido in un altro salvataggio non è attivo nel mondo corrente.

Manifest annidato o ancora compresso

Controlla che manifest.json sia direttamente nella cartella destinata al pack. L'estrazione può aver creato una cartella esterna aggiuntiva.

UUID o versione non corrispondono

Usa UUID e versione header di manifest.json. Non sostituirli con nome cartella, UUID modulo o dati di un pacchetto scaricato in precedenza.

Tipo di pack nella cartella sbagliata

Sposta il comportamento in behavior_packs e le risorse in resource_packs, poi registra ognuno nel relativo JSON del mondo. L'import client non attiva il server.

Dipendenza o esperimento mancante

Controlla le dipendenze del manifest e le note della release specifica. Installa insieme le versioni richieste e verifica gli esperimenti del mondo se necessari.

I giocatori non vedono le risorse

Controlla elenco risorse, richiesta di trasferimento, accettazione client e versione compatibile. Annota la configurazione prima di svuotare una cache; non cancellare subito i mondi server.

Domande frequenti

Domande frequenti sugli add-on per server Minecraft Bedrock

Come aggiungo add-on a un server Minecraft Bedrock?

Su un Bedrock Dedicated Server che gestisci, arresta e salva il mondo, estrai il pack, copia la cartella in behavior_packs o resource_packs e aggiungi UUID e versione header all'elenco JSON corrispondente del mondo attivo. Riavvia e prova una copia prima di usare il salvataggio principale.

Basta aprire un .mcaddon sul server?

Di solito il file viene importato nel profilo di un client Bedrock, non nel mondo dedicato. Estrai le cartelle e segui la procedura BDS. Un hosting può avere un flusso diverso: consulta la documentazione del provider.

Ogni giocatore deve installare lo stesso add-on?

Non sempre. Il server può offrire i resource pack ai client e texturepack-required può richiedere di accettare il file scaricato. I behavior pack vengono configurati con il mondo sul server. Versione, piattaforma, pack e impostazioni continuano a incidere sul risultato.

Come aggiungo più add-on a un BDS?

Installa ogni cartella estratta e registra ciascun pack nell'elenco corretto con il proprio UUID header e versione. Aggiungi le dipendenze dichiarate, evita ID duplicati e procedi un pack alla volta su una copia per individuare conflitti e rispettare l'ordine richiesto.

Posso usare questi passaggi per Minecraft Realms?

No. I percorsi si riferiscono a un Bedrock Dedicated Server gestito dal proprietario. Realms non espone lo stesso file system; usa il flusso supportato dal proprietario del Realm. Anche un hosting gestito può richiedere operazioni nel pannello.

La pagina di Verity Bedrock conferma la compatibilità BDS?

No. La scheda verificata il 23 settembre 2026 indica versione 4.0.0 per V26.50, ma non è un test server dedicato. Confronta manifest e note con la tua build e prova un backup. Il pulsante usa la pagina file ufficiale CurseForge perché non è stato verificato un link binario stabile.

Perché il pacchetto è nella cartella ma non ha effetto sul mondo del server?

Verifica che la cartella appartenga al mondo attivo indicato da level-name e che world_behavior_packs.json contenga UUID e versione dell'intestazione di manifest.json. Il pacchetto può essere presente ma inattivo se è associato a un altro mondo o se i valori del manifesto non corrispondono.

La scheda di rilascio di Verity Bedrock dimostra la compatibilità con il server?

No. La fonte di Verity controllata il 23 settembre 2026 indica la versione 4.0.0 per V26.50, ma una scheda di rilascio non è una prova di compatibilità con un server dedicato. Confronta il manifest del pacchetto e le note della fonte con la build BDS e prova tutto su una copia di backup del mondo. Il pulsante per scaricare Bedrock apre la pagina ufficiale del file su CurseForge, perché non è stato possibile verificare un link diretto stabile.
